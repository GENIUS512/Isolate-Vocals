# Отдельно — разделение вокала и инструментала (версия для Render.com)

Один Docker-контейнер: FastAPI отдаёт и фронтенд, и API разделения звука
через Demucs. Подогнан под бесплатный тариф Render (512 МБ RAM):
обработка идёт кусками по 8 секунд, torch ограничен одним потоком,
лимит файла — 15 МБ / 4 минуты.

Пользователь загружает свой аудиофайл — сервис разделяет его на вокал
и инструментал, даёт послушать оба канала с раздельной громкостью и
скачать в mp3/wav. Скачивание по внешним ссылкам (YouTube и т.п.)
намеренно не реализовано.

## Как задеплоить на Render — без консоли, только веб-интерфейс

### 1. Залей проект на GitHub

Если ещё нет репозитория:
1. Зайди на github.com → **New repository** → дай имя (например `otdelno`) → Create.
2. На странице репозитория нажми **Add file → Upload files**.
3. Перетащи туда всё содержимое этой папки: `main.py`, `Dockerfile`,
   `requirements.txt`, `render.yaml`, папку `frontend/`, этот `README.md`.
4. Внизу нажми **Commit changes**.

### 2. Подключи репозиторий к Render

1. Зайди на render.com → **Sign up** (можно через GitHub-аккаунт — тогда
   меньше полей заполнять, карта не нужна).
2. На дашборде нажми **New +** → **Web Service**.
3. Выбери **Build and deploy from a Git repository** → авторизуй доступ
   к GitHub → выбери свой репозиторий `otdelno`.
4. Render сам увидит `Dockerfile` в корне и предложит **Environment: Docker**
   — оставь как есть.
5. В **Instance Type** выбери **Free**.
6. Нажми **Create Web Service**.

Render сам подхватит и `render.yaml`, если он есть в репозитории —
но даже без него всё соберётся по Dockerfile, `render.yaml` просто
подстраховка.

### 3. Дождись сборки

Первая сборка занимает 10-20 минут — скачивается torch (CPU-версия,
она полегче) и веса модели Demucs. Статус сборки видно прямо на
странице сервиса в Render. Когда появится **Live** — сайт уже работает,
Render сразу даёт URL вида `https://otdelno.onrender.com`.

## Особенности бесплатного тарифа Render

- **512 МБ RAM** — из-за этого в `main.py` включена обработка кусками
  (`--segment 8`) и ограничение `OMP_NUM_THREADS=1`. Это ощутимо медленнее,
  чем без ограничений, зато экономит память.
- **Лимит 15 МБ / 4 минуты** на файл (`MAX_FILE_SIZE_MB`,
  `MAX_DURATION_SEC` в `main.py`) — подобран с запасом под 512 МБ.
  Если сервис всё равно падает по памяти на реальных файлах — это
  первое, что стоит уменьшить ещё сильнее.
- **Засыпание после 15 минут простоя.** Если сайтом никто не пользуется,
  Render "усыпляет" сервис, а следующий запрос ждёт 30-60 секунд, пока
  он проснётся. Это нормально для бесплатного тарифа, не баг.
- **750 часов в месяц** бесплатного времени — с запасом на один
  постоянно работающий сервис (в месяце максимум ~730 часов).
- Карта при регистрации не требуется, если создаёшь аккаунт через
  GitHub-логин.

## Если Demucs всё равно падает по памяти

Признак — статус 500 с ошибкой вида `Killed` или `MemoryError` в логах
Render (вкладка **Logs** на странице сервиса). Что можно сделать, по
нарастанию эффекта:

1. Уменьшить `--segment` в `main.py` с `8` до `4` (медленнее, но легче).
2. Уменьшить `MAX_DURATION_SEC` до 120 (2 минуты).
3. Перейти на облегчённую модель `-n htdemucs_ft` → `-n mdx_extra_q`
   (быстрее и легче, чуть хуже качество разделения).
4. Если ничего не помогает — 512 МБ действительно мало для этой задачи,
   и тогда либо Oracle Cloud (по-настоящему бесплатно, но сложнее
   настроить), либо платный тариф Render Starter (~$7/мес, 2 ГБ RAM).

## Локальный запуск (для проверки перед деплоем)

```bash
pip install -r requirements.txt
uvicorn main:app --host 0.0.0.0 --port 8000
```

Открой http://localhost:8000
